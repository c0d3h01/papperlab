How it works

Three moves. Then it is done.

No onboarding, no “upgrade to export”. Just a clean hand-off between you and the engine.

  1. 01

    Drop the file

    Choose a tool or let PaperLab suggest one from the file type. Everything stays local until you press start.

  2. 02

    Set the job

    Use plain controls for pages, quality and position. Or open the studio when the job needs eyes and hands.

  3. 03

    Take the result

    Watch the progress, then download the finished files. They expire automatically so nothing lingers.

Privacy & housekeeping

Your files are guests, not inventory.

Uploads live in a temporary work directory and are removed after the job window closes. No document library, no training corpus. When you deploy PaperLab yourself, the files never leave your server.

Read the policy
01Expiring jobs

Every job has a TTL. The default is two hours; the server sweeps expired work automatically.

02Cloud only when asked

Processing engines run on the same host. Google Drive is optional: you connect it, pick the files, and the browser talks to Google directly. AI and translation are off unless configured.

03You own the output

No added watermarks, no locked exports, no quiet re-encoding of your originals.

The engine room

Honest about what is running.

PaperLab is a Go service with a static front end. It uses pdfcpu for document structure, Poppler for text and rendering, Ghostscript for compression and PDF/A, qpdf for repair and encryption, Tesseract for OCR, and headless Chrome for the web. Tools that need a missing engine are marked instead of quietly failing.

Built to be yours

A workshop you can take home.

The whole product ships as a Go binary plus static assets. Run it on a laptop, a VPS, or in a container. The API is small and documented by example: upload a job, poll it, download the outputs.

Try the hosted bench
POST /api/jobs
# upload a PDF and start a job
curl -X POST https://your-host/api/jobs \
  -F tool=compress \
  -F options='{"level":"balanced"}' \
  -F files=@report.pdf

# → { "id": "…", "status": "queued" }
curl https://your-host/api/jobs/…
# → outputs[].url, ready to download
